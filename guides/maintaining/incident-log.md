# Registro de incidentes

This is the public stand-in for the team's incident log. The cases that motivated each rule, hook and reviewer of the harness name real clients, projects and machines, so they live in the team's private maintenance repository and are not published. The guides state each rule and the reason for it, without the case. Some scripts and tests still name their case in a comment: that name does not resolve in this copy.

## Por qué esta página está casi vacía

Cada regla, freno o revisor del arnés nació de algo que se rompió, con su fecha y su diagnóstico. Esos casos nombran
clientes, proyectos, personas y máquinas de verdad, así que viven en el **repo de mantenimiento del equipo**, que es
privado, y no se publican.

Las guías dicen la regla y su porqué, sin el caso: se tienen que entender solas. El código es otra cosa: la cabecera
de un guion o de una prueba todavía puede nombrar su caso (`guides/maintaining/incident-log.md#<caso>`). En el repo de
mantenimiento ese nombre lleva al caso completo; en esta copia llega a esta página y **el ancla no resuelve**: no es
un enlace roto, es el caso que no se publica.

## Qué hacer con un nombre de caso que llega acá

- Lo que el comentario dice alcanza para entender por qué el código hace lo que hace.
- El nombre del caso (la parte después de `#`) dice de qué se trató y su fecha.
- Si una regla de una guía no se entiende sin el caso, es un defecto de la guía: abrí un issue que la nombre.
